## 先纠正“网站之外都是新岗位”的判断

[roadmap.sh 路线目录：形式与覆盖对照](https://roadmap.sh/roadmaps) 当前目录已包含 AI Engineer、Inference Engineering、MLOps、AI Red Teaming、Forward Deployed Engineer，以及 AI Agents、Prompt & Context Engineering 等角色或技能路线。它们不能全部被称为“网站尚未覆盖的未来岗位”。

技能路线、岗位职称和公司分工也不是一一对应。NIST 对 occupation、job 与 work role 的区分可帮助避免把每个工作任务都计算成一个新职业，见 [NIST NICE：工作角色、知识与技能](https://www.nist.gov/itl/applied-cybersecurity/nice/nice-framework-resource-center/resources/occupations-jobs-and-work)。

## 网站目录以外，值得进一步展开的工作

- **RL 训练环境与验证器：**把可执行任务、奖励与验证、并行运行和数据回放连接起来。
- **AI 执行沙箱与工具平台：**处理不可信执行、多租户、资源限制、身份与审计。
- **上下文与记忆工程：**管理知识、检索、工具、状态和长任务信息，独立职称尚未统一。
- **人类反馈与训练数据：**规范、质检、一致性、来源、偏差与下游验证形成闭环。
- **模型行为评测与安全：**评测设计、评分校准、污染、红队和风险控制分别需要能力。

招聘实例：[Anthropic 招聘实例：环境、沙箱、评测与系统](https://www.anthropic.com/careers/jobs) 的所查目录包含环境基础设施、沙箱、后训练评测、推理系统等工作；[字节 Seed：高校人才招聘实例](https://seed.bytedance.com/zh/seedearlycareer) 是国内高校人才招聘实例。前者偏前沿 AI 团队，后者也是特定招聘项目，二者都不能代表所有地区与企业。

课程变化实例：[MIT Missing Semester 2026](https://missing.csail.mit.edu/) 的 2026 教学包含 Agentic Coding；[Hugging Face Context Course](https://huggingface.co/learn/context-course/unit0/introduction) 展开技能、工具连接与 Agent 生命周期。它们支持学习新工作方式，不直接证明独立岗位数量或未来薪资。

## 原有路线应该怎样改

以下为作者的综合学习建议，不是对岗位消失的预测。

| 路线族 | 建议增加 | 保留并掌握 | 减少重复训练 |
| --- | --- | --- | --- |
| 软件产品 | 需求与验收规格；AI 编码的上下文、差异审查、测试与回滚；按需集成模型 | 编程、数据建模、调试、网络、安全和可维护性 | 反复手写样板、框架 API 死记、同质化 CRUD 练习 |
| 系统与云 | AI 辅助排障的证据核验；模型工作负载；资源、权限与成本；自动化变更控制 | OS、网络、并发、体系结构、故障模型和测量 | 重复配置与命令记忆；没有测量的调参 |
| 数据与决策 | 生成 SQL 的核验；数据来源与许可；AI 评测数据；结果不确定性与解释 | 统计、口径、数据质量、因果边界和领域理解 | 重复做图与模板报表；堆砌模型名称 |
| AI 与机器学习 | 任务级评测；数据与模型版本；失败恢复；权限、延迟与成本；简单方案基线 | 数学、数据、软件工程、实验设计与独立调试 | 只学框架封装；只调提示词；无验证的榜单追逐 |
| 安全与隐私 | 模型与 Agent 的输入、工具、数据和供应链威胁；AI 检测结果复核 | 授权、根因分析、威胁建模、验证与证据链 | 只依赖扫描器和生成式报告；背漏洞名称 |
| 硬件与实体系统 | AI 辅助 HDL/固件审查；软硬协同；端侧模型；仿真与实机对照 | 电路、时序、控制、调试、功耗和物理约束 | 重复寄存器样板；不带测量的演示 |
| 图形与互动 | AI 素材与代码的许可、质量和管线；生成内容可控性；真实交互评测 | 几何、渲染、性能、交互和美术流程 | 仅复制教程场景；手工重复资产流程 |
| 产品设计与交付 | AI 能力边界；人机接管；任务级评测；成本、数据与供应商约束 | 用户研究、沟通、判断、业务与交付责任 | 模板 PRD/幻灯片；无用户证据的原型数量 |
| 科研与行业交叉 | AI 文献检索核验；辅助实验；数据污染、复现与领域有效性 | 数学证明、研究设计、学科基础和独立贡献 | 无问题意识的论文收集；重复低价值实验 |
| 升学与职业形态 | 形成可核验的个人贡献；AI 辅助材料查错；核对当年资格、费用与规则 | 基础、诚信、沟通、交付与持续学习 | 模板化材料；证书堆积；将工具熟练度当全部竞争力 |

各独立路线还有本方向的具体调整。减少样板、死记 API 和重复界面练习，不等于无需理解语法、数据库、网络或算法；初学者仍需足够独立实现建立判断能力。

## 所有路线的共同 AI 能力

```mermaid
flowchart LR
  A["描述任务与验收"] --> B["提供适当上下文"]
  B --> C["受控生成或执行"]
  C --> D["审查、测试与来源核验"]
  D --> E["测量质量、时间与成本"]
  E --> F["交付、监控与修正"]
```

1. 说明输入、输出、限制、可接受错误与验收方法。
2. 提供必要代码、资料、版本和权限，避免无目的堆积上下文。
3. 对执行、文件、凭证、工具和外部副作用设边界。
4. 阅读改动，查原始文档，验证引用、数据与依赖。
5. 与简单方案比较，关注失败分组、维护成本和恢复。
6. 保留独立调试、解释与修改能力，遵守课程和组织规则。

## 不应推出的结论

- 有了 Agent，不代表每个任务都需要多智能体。
- API 调用、模型微调、模型研究与推理优化不是同一能力。
- 一个热门新职称不能证明稳定收入或广泛应届入口。
- 少量海外前沿团队的招聘不能直接外推国内需求。
- AI 提高某项任务速度，不代表整个岗位价值等比例减少。
