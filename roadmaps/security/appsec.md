## 开始前

网络、OS、编程与安全基础；研究型密码学另补代数、概率和证明；所有攻击实践限授权对象。

先阅读[四年共同主干](../../docs/foundation.md)。已掌握的内容通过习题或项目验收，不重复完整刷课。各分支是可选择的发展方向，不是同一学生的全部必修。

## AI 时代怎样修改这条路线

**本路线重点：** 增加生成代码、模型接口与 Agent 工具的威胁建模；保留身份权限、根因和修复验证。

| 调整 | 建议 |
| --- | --- |
| 增加 | 模型与 Agent 的输入、工具、数据和供应链威胁；AI 检测结果复核 |
| 保留并扎实掌握 | 授权、根因分析、威胁建模、验证与证据链 |
| 减少重复训练 | 只依赖扫描器和生成式报告；背漏洞名称 |
| 必须识别的风险 | 忽视越权、提示注入和敏感数据；混淆猜测与已验证漏洞 |

减少重复训练不等于跳过基础。AI 生成的结果仍需由提交者验证；具体课程与工作单位的工具规则优先。上述调整是规划建议，不能推出某个岗位将消失。相关参考：[OWASP GenAI Security](https://genai.owasp.org/llm-top-10/)。

## 代表作与能力验收

**项目：** 授权应用的评估和修复。

**关键验收：** 明确攻击条件、影响与回归。

- [ ] 需求、输入、输出和限制明确。
- [ ] 代码、数据或案例来源清楚，环境与步骤可复现。
- [ ] 记录个人贡献，能脱离 AI 解释关键机制并完成现场修改。
- [ ] 有针对本路线的测试、对照、用户验证或论证。
- [ ] 保留失败案例、误差或限制，而非只展示成功结果。
- [ ] 至少获得一次外部审查：实习、开源、导师、同伴或真实用户反馈。

这是一组能力证据，不是录用保证。具体简历和选拔准备见[求职、升学与作品集](../../docs/evidence-and-entry.md)。

## 后续发展与投入

可延伸到：**产品安全、云安全**。转向时先补目标路线的先修，不必从所有基础课重来。

本科阶段以初级入口或研究训练为目标；长远职级需要真实经验。

硬件路线先用仿真和学校设备；AI 路线先做小规模正确性实验并设算力预算；行业与研究路线先确认数据、导师或领域资源。不要只按路线名称购买培训或设备。
