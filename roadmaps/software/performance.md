## 开始前

编程、数据结构、Git、调试与测试；再按路线补网络、数据库或平台基础。

先阅读[四年共同主干](../../docs/foundation.md)。已掌握的内容通过习题或项目验收，不重复完整刷课。各分支是可选择的发展方向，不是同一学生的全部必修。

## 阶段学习清单

| 建议窗口 | 课程主题与实践 |
| --- | --- |
| 大二上：方向起步 | 系统；编程；统计；测量 |
| 大二下：主线方法 | 剖析；基准；负载模型 |

## AI 时代怎样修改这条路线

**本路线重点：** 增加模型调用与 Agent 的负载、质量约束、成本测量；保留可复现基准和瓶颈分析，避免只比较单次速度。

| 调整 | 建议 |
| --- | --- |
| 增加 | 需求与验收规格；AI 编码的上下文、差异审查、测试与回滚；按需集成模型 |
| 保留并扎实掌握 | 编程、数据建模、调试、网络、安全和可维护性 |
| 减少重复训练 | 反复手写样板、框架 API 死记、同质化 CRUD 练习 |
| 必须识别的风险 | 把生成速度误当工程能力；没有理解就接受修改 |

减少重复训练不等于跳过基础。AI 生成的结果仍需由提交者验证；具体课程与工作单位的工具规则优先。上述调整是规划建议，不能推出某个岗位将消失。相关参考：[MIT Missing Semester 2026](https://missing.csail.mit.edu/)。

## 代表作与能力验收

**项目：** 一个真实项目的性能改进。

**关键验收：** 正确性不退化，测量无偏且可重现。

- [ ] 需求、输入、输出和限制明确。
- [ ] 代码、数据或案例来源清楚，环境与步骤可复现。
- [ ] 记录个人贡献，能脱离 AI 解释关键机制并完成现场修改。
- [ ] 有针对本路线的测试、对照、用户验证或论证。
- [ ] 保留失败案例、误差或限制，而非只展示成功结果。
- [ ] 至少获得一次外部审查：实习、开源、导师、同伴或真实用户反馈。

这是一组能力证据，不是录用保证。具体简历和选拔准备见[求职、升学与作品集](../../docs/evidence-and-entry.md)。

## 后续发展与投入

可延伸到：**HPC、系统、推理优化**。转向时先补目标路线的先修，不必从所有基础课重来。

本科阶段以初级入口或研究训练为目标；长远职级需要真实经验。

硬件路线先用仿真和学校设备；AI 路线先做小规模正确性实验并设算力预算；行业与研究路线先确认数据、导师或领域资源。不要只按路线名称购买培训或设备。
